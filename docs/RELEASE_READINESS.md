# macOS 发布准备状态

GitHub 源码已选择 GNU AGPL 3.0 分发路线。当前 Apple Silicon 应用已经能用于本机验收，但尚未达到正式对外发行状态。

## 已完成

- 完整 `.app` 可以启动内置 Qwen3 4B 与 BGE 模型并打开浏览器工作台；
- 主程序和 `llama-server` 均为 arm64；
- `Info.plist`、ad-hoc 深度签名、HTTP 启动和无残留退出检查通过；
- 文档导入、限定来源问答、大纲、自测、持久化、删除保护和重新导入已经走过真实应用链路；
- 当前代码的 293 项普通测试、编译和差异检查通过；
- 应用体积约 3.5 GB，其中模型目录约 2.4 GB，Qwen GGUF 单文件约 2.3 GB；其余大项主要是 PyTorch、PyArrow、Gradio、ONNX Runtime、ChromaDB 和 PDF 解析运行库。
- 项目许可证已从 MIT 调整为 GNU AGPL 3.0，与 PyMuPDF/PyMuPDF4LLM 的免费许可路线一致；GitHub 仅分发源码，不包含当前应用包。

## 尚未完成

1. **可复现的推理二进制**：当前构建脚本接收本机路径，本次包内 `llama-server` 来自已安装的 Ollama 应用，报告为开发构建。正式发行应改用明确上游版本和可复现构建来源。
2. **发行版本**：`CFBundleShortVersionString` 目前仍是 `0.0.0`。应在确定首个发行范围后设置真实版本，不提前虚构版本号。
3. **完整第三方声明**：已整理直接依赖、模型和推理程序；传递依赖许可证及 Apache NOTICE 仍需在最终依赖集合上核对。
4. **对应源码与构建材料**：若发布二进制，需要确保同一版本的源码和构建脚本可获取，并清楚说明模型与运行组件的取得方式。
5. **Apple 分发手续**：当前只有 ad-hoc 签名，尚未使用 Developer ID 签名，也未公证。
6. **平台范围**：当前只验证 Apple Silicon macOS；Windows 启动器和其他平台没有真机发布验收。

## 推荐顺序

1. 先把当前源码、AGPL 许可证和第三方说明提交到 GitHub；本科项目可以只交付源码。
2. 功能和文档稳定后创建源码版 GitHub Release，由 GitHub 自动生成源码压缩包，不上传当前 3.5 GB 应用。
3. 只有确定需要发布 macOS 二进制时，再设置发行版本，固定 `llama-server` 来源并完成传递依赖许可证清单。
4. 重建应用，验证对应源码、许可证文件、功能和退出行为。
5. 使用 Developer ID 签名并提交 Apple 公证。
6. 用干净用户目录完成最后一次安装、首次启动、资料持久化和升级验收。

当前不需要为了源码交付删除 PDF 表格、公式、跨页或图形能力，也不需要重写解析器。
